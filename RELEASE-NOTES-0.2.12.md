# Seylo 0.2.12

Update from Settings > Updates: the panel updates first, then each node. Nothing to run on the servers. New installs: `curl -fsSL https://install.seylo.dev | sudo sh`.

What's new in full: https://docs.seylo.dev/self-hosting/whats-new-in-0-2-12

## Improved

- **A clone keeps Deploy on push.** Cloning an app built from a repository (GitHub, a git URL, GitLab, Gitea or Bitbucket) used to turn Deploy on push off on the clone. It now keeps the source's setting, and the Clone dialog has a "Deploy on push" switch that starts as the source's, with a note that each push to the branch then deploys both services. A clone that deploys on push picks up the next push to its branch: through the GitHub App like the source, and for a repository read through the connected GitHub account or a GitLab, Gitea or Bitbucket connection through a repository webhook of its own, created with the clone (polled every minute while the webhook cannot be created, as for any other service). A push that arrives while the clone's data is still being copied waits for the copy: once it is done, the clone deploys the head of its branch, and the webhook's delivery log says so (a copy that failed deploys nothing). A git URL deploys on push through a deploy trigger URL, which a clone does not copy: make one on the clone's Source tab. Export and import are unchanged: an imported service still arrives with Deploy on push off unless you turn it on in the import. In the API and MCP: `services.clone` takes `deployOnPush`; left out, the clone keeps the source's setting.
- **References show a database's internal address on other nodes too.** On the Environment tab, the References panel used to leave out `INTERNAL_URL` and `INTERNAL_HOST` of an exposed database (or an app with a domain) running on another node than the service you edit, so they looked missing. They are listed again, struck through like those of services with no way in, and their tip says which variable to use instead, for example "Only for services on il-ra. api runs on empire, so use EXPOSED_URL." The project network does not reach across nodes, so the exposed URL is still the one that connects.
